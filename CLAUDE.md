# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

CertifyApp is a Windows-only WPF desktop clone of *Certify The Web*: it manages ACME v2 certificates (Let's Encrypt, ZeroSSL, Google Public CA, custom ACME directory) and deploys them to IIS, Apache or Nginx. The .NET 8 solution file is `CertifyApp.slnx`. README.md is in Polish and is the feature spec.

## Commands

```powershell
dotnet build                                              # whole solution
dotnet run --project src/Certify.WPF/Certify.WPF.csproj   # GUI
dotnet run --project src/Certify.WPF/Certify.WPF.csproj -- --renew   # headless renew pass, then exit
dotnet publish src/Certify.WPF -c Release -r win-x64 --self-contained false
powershell -File tools\Build-Installer.ps1                # NSIS installer -> artifacts\CertifyApp-Setup-<version>.exe
dotnet test                                               # xUnit, tests/Certify.Tests
dotnet test --filter "FullyQualifiedName~RenewalServiceTests"            # one class
dotnet test --filter "FullyQualifiedName~DnsChallengeTests.DnsTxtValue_MatchesCertesDnsTxt"  # one test
```

- `tests/Certify.Tests` covers Core, ACME and Deployment with no network access, IIS or admin rights. The WPF code-behind has no tests. Shared helpers in `TestHelpers.cs` are `TempDir` (a temporary DataDirectory), `TestChain` (a generated root → intermediate → leaf certificate chain) and `ListLog` (a synchronous `IProgress`). `RenewalTests.cs` contains the `FakeCa` and `FakeDeployer` fakes.
- `UIStrings.Lang` is static. Tests that switch the language or assert on localized text belong in `[Collection(nameof(LanguageCollection))]`, which runs without parallelization.
- Some tests start real processes (`cmd.exe`, `net`) and therefore need Windows.
- The app requires Administrator rights. If it starts without them, `App.OnStartup` relaunches itself through UAC (`AdminHelper`, `Verb = "runas"`) and exits. Do not switch to a `requireAdministrator` manifest, because the app is published via ClickOnce (`Properties/PublishProfiles/ClickOnceProfile.pubxml`) and ClickOnce rejects that manifest. To debug, run Visual Studio as Administrator; otherwise the relaunched process is not attached to the debugger.
- `App.xaml` has no `StartupUri`. `App.OnStartup` creates `MainWindow` itself, after the elevation check and the `--renew` branch.
- Live ACME orders need a public host with port 80 open, or a DNS zone on Cloudflare or Route53. Use the `LetsEncryptStaging`/`GoogleStaging` CAs (or a Pebble custom URL) when testing.
- `AssemblyVersion` is set separately in each `.csproj` and uses a date-based format `yy.M.d.build` (e.g. `26.10.4.1`). When bumping the version, keep all projects equal. The main window's title shows the `Certify.WPF` version (`AppInfo.Version`).
- The NSIS installer (`installer/CertifyApp.nsi`, needs NSIS 3; compiled directly without `/D` parameters it reads the version from the csproj and runs `dotnet publish` itself) installs the flat publish output to `%ProgramFiles%\CertifyApp`, so the service directory `CertifyApp\Service` is a subdirectory of the app; `WindowsServiceManager.SourceFiles()` excludes it when copying. Upgrade and uninstall delete only `*.dll/*.exe/*.json/*.pdb` in the install dir, so a publish with subdirectories needs the script updated. The uninstaller removes the `CertifyAppRenewal` service and deletes `%ProgramData%\CertifyApp` only on explicit confirmation. Version comes from `AssemblyVersion` in `Certify.WPF.csproj`.
- License: PolyForm Noncommercial 1.0.0 (`LICENSE.txt`), shown on the installer's license page.
- The GUI project builds `CertifyApp.exe` (`<AssemblyName>` in `Certify.WPF.csproj`); the namespace stays `Certify.WPF`.
- The icon is `src/Certify.WPF/Assets/certify.ico`, embedded in the exe via `<ApplicationIcon>` and as a WPF `<Resource>` for the windows. It is generated by `Assets/make-icon.ps1` (System.Drawing; 256 px as PNG, smaller sizes as DIB) and regenerated with `powershell -File Assets\make-icon.ps1 -OutIco Assets\certify.ico`. The NuGet `PackageIcon` must be PNG, so `Assets/certify.png` (128 px, same drawing) is generated with `-OutPng Assets\certify.png`; regenerate both when the icon changes. `AppInfo.RegisterWindowIcon()` sets the icon on all windows, so `Icon=` is not needed in the XAML files.

## Architecture

Projects and their references: `Certify.Core` ← `Certify.ACME`, `Certify.Deployment` ← `Certify.Service` ← `Certify.WPF`.

- **Certify.Core** has no UI and no ACME dependencies. It holds the models, JSON persistence and orchestration. Its key contracts live in `Services/CertificateService.cs`:
  - `ICertificateAuthorityProvider` (Request/Renew), implemented by `Certify.ACME.LetsEncryptService` for every CA, not just Let's Encrypt.
  - `IDeploymentTarget`, implemented by `IisDeployer`, `ApacheDeployer` and `NginxDeployer`. They are matched on `DeploymentTargetType`. On Windows, Apache/Nginx restart the service named in `DeploymentTarget.ServiceName`; if it is empty or missing they detect an `Apache*`/`nginx*` service (`WindowsServiceHelper`, via `sc query`). Nginx without a service falls back to `nginx -s reload`, run from the `nginx.exe` found next to the config (`NginxDeployer.FindNginxExe`).
  - `RenewalService` runs the full pipeline: pre-request tasks → CA order → deploy → deployment tasks → history entry → store upsert → email digest. Despite its file name, `CertificateService.cs` holds this class.
- **Certify.ACME** has two order flows:
  - DNS identifiers use **Certes** (`LetsEncryptService.ProcessOrderAsync`).
  - If any identifier is an IP address (`IdentifierClassifier.IsIp`), the whole order goes to `IpOrderProcessor`, a hand-written RFC 8738 client built on `RawAcmeClient` + `AcmeJws` (ES256 JWS, nonces, POST-as-GET), because Certes only supports DNS identifiers.
  - Do not use Certes's `CertificateChain.ToPem()` or `ToPfx()`. Both check the chain against Certes's built-in list of trusted roots and reject ZeroSSL's chain (Sectigo, cross-signed). Artifacts are built from the raw chain by `LetsEncryptService.BuildArtifacts`, and the PFX by `CertificateArtifactWriter.BuildPfx` in plain .NET.
  - Every ACME network call in both flows is wrapped in `AcmeRetry.ExecuteAsync(...)`, which uses the classification and backoff from `Core/Services/AcmeRetryPolicy`. Wrap new ACME calls the same way.
  - Challenges implement `IChallengeHandler` (Prepare/Cleanup). Http01 writes to the webroot, and the per-domain root comes from `ChallengeConfig.HttpChallengeRootPaths` with `HttpChallengeRoot` as the fallback. DNS handlers come from `ChallengeHandlerFactory.CreateDns`: Manual, Cloudflare, or Route53, which signs requests itself with `SigV4Signer` and does not use the AWS SDK.
  - `AcmeAccountManager` caches ES256 account keys per directory URL + email in `acme_accounts.json`, with EAB (HS256) for ZeroSSL and Google.
- **Certify.WPF** uses code-behind windows, not MVVM; `MainWindow.xaml.cs` holds a small `ManagedCertificateViewModel`. `App.OnStartup` handles the `--renew` headless mode (Task Scheduler) by building the services manually and logging to `logs/renew-<date>.txt`. Background renewal while the GUI runs is `BackgroundRenewalService`, every 12 h. GUI operations (`RunWithProgress`, edit/delete) and the background pass share `RenewalService.OperationLock`, so only one certificate operation runs at a time. New operations that write certificates must take this lock. The lock is a `CrossProcessLock` (local semaphore + `operation.lock` opened with `FileShare.None` in the DataDirectory), so it also excludes the Windows service and `--renew` running in other processes.
- **Certify.Service** is a Worker (`UseWindowsService`, service name `CertifyAppRenewal`, LocalSystem) whose `RenewalWorker` reloads settings and runs `CheckAndRenewAllAsync` every `RenewalCheckInterval`, logging to `logs/service-<date>.txt`. `RenewalHost.Create` builds the headless `RenewalService` for both the service and `--renew`. WPF references the project only so `Certify.Service.exe` lands in its output. `WindowsServiceManager` (WPF, opened via `ServiceWindow`) copies the whole app directory to `%ProgramFiles%\CertifyApp\Service` (ClickOnce's own directory changes on every update) and registers it with `sc.exe`. `MainWindow` refreshes those files on startup when they differ from the app's, and stops its in-process `BackgroundRenewalService` while the service is running.

### Persistence

All state is JSON under `AppSettings.DataDirectory` (`%ProgramData%\CertifyApp\`): `managed_certificates.json` (`CertificateStore`), `appsettings.json` (`SettingsStore`), `acme_accounts.json`, `certs/<id>/` (pfx with password `certify`, crt, key, chain.pem), `logs/`. Secrets are stored in plain text. They are encrypted only in `.cbak` backups (`BackupEncryption`: PBKDF2-SHA256 → AES-256-GCM). If you add a file under the data directory, also handle it in `BackupService` export and import. Import rewrites paths for the local machine.

### Localization

- Every user-facing string is a key in `Certify.Core/Localization/UIStrings.cs` with a `(Pl, En)` pair.
- Code calls `UIStrings.T("Key", args)` (or `WpfLocalizer.T`).
- XAML uses `{DynamicResource Key}`. `WpfLocalizer.ApplyLang` rebuilds a merged ResourceDictionary at runtime, so a language switch takes effect live.
- When you add UI text, add the key with both languages. An unknown key renders as the raw key name.
- `UIStrings.Languages` lists 20 languages. PL/EN live in `UIStrings.cs`; the other 18 are embedded JSON files `Certify.Core/Localization/Translations/<code>.json` (key → text, a missing key falls back to English). A new key must also be added to every JSON file; `Translation_HasEveryKey_WithEnglishPlaceholders` checks keys, `{n}` placeholders and the 7-item `Cal_Dow`.
- Localized buttons use `MinWidth`, not `Width`, so longer translations widen the button. `powershell -File tools\Check-TextWidth.ps1` measures every language against buttons and DataGrid headers that still have a fixed `Width` and exits 1 on overflow.
- `Language = "Auto"` resolves to the OS UI language when it is supported, otherwise English. `ar`/`fa` switch windows to `FlowDirection.RightToLeft` (`WpfLocalizer`). `RenewalHost.Create` sets the language for the service and `--renew` too.
- Log messages (`log?.Report("[ACME] ...")`, `[Renewal]`, `[Deploy]`) are deliberately in Polish and are not localized. Keep the `[Area]` prefix convention.

## Conventions

- Code comments are in Polish, mostly without diacritics. Source files are UTF-8, mostly without a BOM. Preserve Polish characters when editing (Windows PowerShell 5.1 shows them as mojibake on read).
- Long-running operations take `IProgress<string>? log` and `CancellationToken ct` and report progress through `log`. Keep that signature shape.
- `Nullable` and `ImplicitUsings` are enabled in all projects. Core/ACME/Deployment target `net8.0` and only WPF targets `net8.0-windows`. Despite that, `IisDeployer` uses `Microsoft.Web.Administration` and the Windows certificate store.
